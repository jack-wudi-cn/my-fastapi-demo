# 软件工程核心概念与标准开发流程（SDLC）学习笔记

> **文档说明**：本文档梳理了现代软件工程中常见的专有名词、标准开发步骤，以及需求管理的方法论，用于指导后续的项目架构设计与开发实践。

## 一、 核心专有名词辨析

在软件工程中，很多词汇虽然经常听到，但极易混淆。以下是标准定义与区别：

### 1. PRD（产品需求文档） vs 生产环境（Production）
| 概念 | 全称 | 含义 | 对应阶段 |
| :--- | :--- | :--- | :--- |
| **PRD** | Product Requirements Document | 产品经理编写的“施工图”，描述要做什么功能、达到什么目的、不做什么。 | 软件开发最前期（需求阶段） |
| **Production** | 生产环境（简称 Prod） | 真实用户正在使用的线上服务器环境。与之对应的还有 Dev（开发环境）、Test（测试环境）。 | 软件部署后的运行阶段（运维阶段） |

**结论**：PRD 是纸面上的文档；Production 是跑在服务器上的真实环境。两者毫无关系。

### 2. User Story（用户故事）
- **定义**：敏捷开发中描述需求的标准模板。
- **标准公式**：**作为** [角色]，**我想要** [功能]，**以便于** [商业价值/目的]。
- **作用**：强迫研发团队站在“用户视角”思考，而不是单纯接收“写个接口”的指令。它是现代敏捷开发中最小的任务拆解单位。

### 3. AC（验收标准） vs Unit Test（单元测试）
这两个概念经常被混为一谈，实际上是“业务”与“代码”的区别：
- **AC（Acceptance Criteria）**：业务级别的测试题。由产品经理/业务方提出。例如：“金额大于 10000 必须触发预警”。
- **Unit Test（单元测试）**：代码级别的测试脚本。由开发人员编写。例如代码中的 `assert check_amount(15000) == True`。
- **两者的关系**：**AC 是靶子，单元测试是子弹。** 开发人员根据 AC 编写对应的单元测试。当单元测试全部绿灯跑通，代表满足了 AC。

## 二、 标准软件开发生命周期（SDLC）全景图

一个工业级的软件项目，绝不是“打开 IDE 就开始敲代码”，而是需要经历以下六个标准阶段：

### 1. 需求阶段（Requirement）
- **产出物**：MRD（市场需求文档）、**PRD（产品需求文档）**。
- **核心内容**：明确业务背景、目标、User Story、AC、以及边界划定（In-Scope 与 Out-of-Scope）。

### 2. 设计阶段（Design）
- **产出物**：**TDD（技术设计文档）**。
- **核心内容**：
  - 架构图（微服务还是单体？技术栈选型？）
  - 数据库设计（Database Schema）
  - 接口契约（API Contract）
  - 状态机流转图

### 3. 开发阶段（Development）
- **核心动作**：
  - 使用 Git 进行版本控制（分支管理、Commit 规范）。
  - Vibe Coding（借助 AI 辅助编写代码）。
  - Code Review（代码合并前的同行评审）。

### 4. 测试阶段（Testing）
- **核心动作**：
  - **Unit Test**（单元测试：测代码函数）。
  - **Integration Test**（集成测试：测两个服务联调）。
  - **UAT**（User Acceptance Testing：业务方亲自验收）。

### 5. 部署阶段（Deployment）
- **核心动作**：
  - 编写 Dockerfile 进行环境打包。
  - **CI/CD**（持续集成/持续部署）：如 GitHub Actions，实现代码提交后自动测试、打包、上云。

### 6. 运维阶段（Operations）
- **核心动作**：
  - 日志收集（Logging）与链路追踪（Tracing）。
  - 服务器监控（Monitoring）与报警。

## 补充：Git 基础概念

### 1. `git init` 是什么意思？
- **真实含义**：在项目文件夹中初始化一个隐藏的 `.git` 目录，相当于给这个文件夹装上了“版本控制的大脑”。
- **通俗比喻**：相当于去工商局注册了一个“空壳公司”，拿到了营业执照。此时里面还没有员工，也没有业务（没有任何版本记录）。
- **真正的“建立初始版本”**：需要三步走：
  1. `git init`（建空账本）
  2. `git add .`（把文件放进购物车，准备记录）
  3. `git commit -m "xxx"`（正式盖章，产生第一个正式版本记录）
